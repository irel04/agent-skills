# Create PR Skill

This skill chains two steps:
1. **`create-summary`** — runs tests, diffs, and formats a PR description
2. **GitHub MCP** — opens the actual pull request using that description

---

## Execution Flow

```
[User asks for PR]
        │
        ▼
┌─────────────────────┐
│  Phase 1: Summary   │  ← create-summary workflow
│  (always runs first)│
└────────┬────────────┘
         │ summary output
         ▼
┌─────────────────────┐
│  Phase 2: Confirm   │  ← show summary, ask to proceed
│  (user reviews)     │
└────────┬────────────┘
         │ user approves
         ▼
┌─────────────────────┐
│  Phase 3: GitHub MCP│  ← create_pull_request via MCP
│  (opens the PR)     │
└─────────────────────┘
```

## Phase 1 — Run create-summary

Follow the full `create-summary` workflow. Key steps:

### 1a. Pre-flight Check
```bash
git rev-parse --abbrev-ref HEAD          # current branch
git remote get-url origin                # repo remote URL
git fetch origin
git log origin/main...HEAD --oneline     # commits ahead
```

Detect base branch priority: `development` → `develop` → `main` → `master`

### 1b. Run Tests
Check in order:
- `npm test` if `package.json` exists
- `pytest` if Python project
- `cargo test` if Rust
- `go test ./...` if Go

On test failure → report failures, ask: _"Tests are failing. Continue with PR anyway, or fix tests first?"_

### 1c. Analyze Diff
```bash
git diff origin/<base-branch>...HEAD --stat
git diff origin/<base-branch>...HEAD
git diff --staged
```

If **no diff**: stop and report — _"No changes detected between `<current-branch>` and `<base-branch>`. Nothing to PR."_

### 1d. Generate PR Description
Check for PR templates in this order:
1. `.github/PULL_REQUEST_TEMPLATE.md`
2. `.gitlab/merge_request_templates/*.md`
3. `CONTRIBUTING.md`
4. Use the default template below

**Default PR Description Template:**
```markdown
## 📌 Summary
<auto-generated concise overview>

---

## 🎯 Type
- [ ] Feature
- [ ] Bug Fix
- [ ] Refactor
- [ ] Test
- [ ] Documentation
- [ ] Configuration
- [ ] Performance
- [ ] Security
- [ ] Tech Debt

---

## 📊 Change Statistics
- **Files changed:** X
- **Insertions:** +XXX
- **Deletions:** -XXX

---

## 🔧 Modified Components
### Source Code
- `path/to/file` — brief description

### Tests
- `path/to/test` — additions/modifications

### Configuration
- `file` — what changed

---

## 🧠 Context / Background
- **Related issues:** #XXX
- **Breaking changes:** Yes / No
- **Migration required:** Yes / No

---

## ✅ Testing
- [ ] Unit tests passing
- [ ] Integration tests passing
- [ ] Manual testing completed

**Test results:** <auto-populated>

---

## 🚀 Deployment Notes
- [ ] DB migrations required
- [ ] Env variables added/changed
- [ ] Rollback plan documented
```

## Phase 2 — User Review & Confirmation

After generating the summary, display it and ask:

> _"Here's the PR description I've generated. Does this look good? I'll use this to open the pull request on GitHub. You can also tell me:_
> - _The target branch (default: `<detected-base-branch>`)_
> - _PR title (default: auto-generated from summary)_
> - _Whether the PR should be a **draft**_
> - _Any reviewers or labels to add"_

Wait for explicit confirmation before proceeding to Phase 3.

---

## Phase 3 — Create PR via GitHub MCP

Once the user confirms, use the GitHub MCP `create_pull_request` tool.

### Required Parameters
| Parameter | Source |
|-----------|--------|
| `owner` | parsed from `git remote get-url origin` |
| `repo` | parsed from `git remote get-url origin` |
| `title` | generated from summary (or user override) |
| `body` | full PR description from Phase 1 |
| `head` | current branch name |
| `base` | detected or user-specified base branch |

### Optional Parameters (if user specified)
| Parameter | Value |
|-----------|-------|
| `draft` | `true` if user wants draft PR |
| `reviewers` | array of GitHub usernames |
| `labels` | array of label strings |

### Parse Remote URL
```javascript
// Examples:
// https://github.com/owner/repo.git  → owner=owner, repo=repo
// git@github.com:owner/repo.git      → owner=owner, repo=repo
const remoteUrl = execSync('git remote get-url origin').toString().trim();
const match = remoteUrl.match(/github\.com[:/](.+?)\/(.+?)(?:\.git)?$/);
const [owner, repo] = [match[1], match[2]];
```

### MCP Call
```json
{
  "tool": "create_pull_request",
  "owner": "<parsed-owner>",
  "repo": "<parsed-repo>",
  "title": "<pr-title>",
  "body": "<pr-description>",
  "head": "<current-branch>",
  "base": "<base-branch>",
  "draft": false
}
```

### On Success
Report back:
```
✅ Pull Request created!
   Title: <title>
   URL:   https://github.com/<owner>/<repo>/pull/<number>
   Base:  <base-branch> ← <current-branch>
   Draft: Yes / No
```

## Error Handling

| Scenario | Action |
|----------|--------|
| Not a git repo | Stop: _"Not a git repository. Navigate to your project root."_ |
| No GitHub remote | Stop: _"No GitHub remote found. Add one with `git remote add origin <url>`"_ |
| Branch not pushed | Prompt: _"Branch hasn't been pushed yet. Should I push it first with `git push -u origin <branch>`?"_ |
| PR already exists | Report: _"A PR for this branch already exists: <url>. Want to update the description instead?"_ |
| Tests failing | Ask: _"Tests are failing. Open as draft PR, or fix tests first?"_ |
| No diff | Stop: _"No changes to PR. The branch is in sync with `<base>`."_ |
| MCP auth error | Report: _"GitHub MCP authentication failed. Make sure the GitHub MCP server is connected in your Claude settings."_ |

## Configuration (optional, `.claude/pr-config.json`)

```json
{
  "defaultBaseBranch": "main",
  "defaultDraft": false,
  "defaultReviewers": ["username1"],
  "defaultLabels": ["needs-review"],
  "skipTests": false,
  "autoConfirm": false
}
```

If `autoConfirm: true`, Phase 2 review is skipped and PR is created immediately after summary.
